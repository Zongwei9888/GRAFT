## Fixed runtime and method

- Harbor `0.20.0`, official Terminal-Bench Git tag `v3.0.0`;
- Codex CLI `0.147.0`, `gpt-5.6-sol`, high reasoning;
- GRAFT commit `85043df056dd9967f3f88ab036e47eda93911d0b`;
- no task profile, benchmark route, fixed verifier command, fixture, or hidden-test information;
- candidate generated by Native Codex before GRAFT modeling;
- at most seven dynamically planned verifiers, all run in disposable copies for the measurement
  matrix; producer source must remain byte-identical;
- Original selector nominal budget `4.0` for the primary GRAFT branch;
- only blocking, event-matched, requirement/authority-grounded, portable evidence may be fed back;
- safe unwrapping of a single shell-transport command follows `AMENDMENT-03.md`;
- at most one same-thread continuation and one promotion pass per task in this gate.

The official evaluator sees the exact first candidate before any GRAFT feedback and the exact final
candidate after continuation or No-Op. It is never visible to graph construction, selection,
verification, feedback, or promotion.

## Resource gate

The run-all matrix is experimental measurement overhead, not product policy. Across the two new
tasks, stop launching additional matrix tasks if either accumulated bound is reached:

- 4,000,000 child-model input tokens, counting modeling and all shadow verifiers; or
- 30 minutes of matrix-only wall time.

An already running task is allowed to close. Infrastructure failures are diagnosed and may receive
one transport-only retry; model/evaluator outcomes are never retried. A planner returning more than
seven verifiers censors the matrix row instead of choosing a convenient subset.

## Outcomes

For each task report:

- first-candidate official reward;
- graph counts, selected set, expected coverage, residual risk, and high-order edges;
- eligible evidence and its exact portable reproductions;
- same-thread continuation versus No-Op;
- promotion state and official post-feedback reward;
- causal `delta_feedback`;
- producer, modeling, verifier, continuation, promotion, and wall costs separately.

Cohort summaries report both task success and feedback effects, including regressions. A positive
method gate requires at least one exact-candidate repair (`delta_feedback=+1`), no regression, and
all continuation evidence satisfying promotion provenance. Otherwise the method remains unproven.
Regardless of outcome, two tasks cannot establish statistical significance or graph superiority.
